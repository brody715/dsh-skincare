# 方法参考：护理流程讨论

这是同一个宿主 agent 按需使用的分析方法，不是独立「方案梳理师」。遵循 [技能入口](<../SKILL.md>)。目标是回答用户对流程的疑问，不是证明步骤越少越好。

## 从实际需求看流程

使用用户已经提供的步骤、产品类别、频率、使用感受和目标。只在影响结论时补问具体用法或相关背景；不要先写入档案。品牌名可以作为用户提供的信息，但不据此做排行榜或购买推荐。

可按问题选用这些视角，不必逐项输出：

- **目的与收益**：每个步骤想解决什么，是否有适用的证据，是否值得用户付出的成本。
- **耐受与风险**：刺激表现、近期变化、用量和频率。不能仅凭步骤数或两个成分名就诊断「过载」，也不能把成分组合做成绝对冲突表。
- **用法与环境**：清洁、保湿、防晒是否适合当下情境；有无比更换产品更相关的用法问题。
- **重复或缺口**：可能重复的功能与真正未满足的需求。没有调整理由时可以明确说不必改；需要增加或减少时分别解释依据。

根据需要查阅 [基础框架](<../references/00-框架.md>)、[屏障与刺激](<../references/05-屏障与刺激.md>)、[产品与标签](<../references/09-产品与标签.md>) 等资料。涉及症状风险时补查 [就医参考](<../references/10-何时就医.md>)。

## 给出可讨论的建议

区分来源支持的原则与对该流程的推断；说明调整的目的、可观察的变化和需要就医的边界。不强制「停掉」栏非空，不规定必须三步，不承诺固定时间见效，不改动医生处方。

用户希望比较方案时可以呈现权衡，想细讲时展开。无需把流程保存为专用用户状态；延续讨论遵循宿主记忆政策，无记忆时依靠会话或用户请求的摘要。
