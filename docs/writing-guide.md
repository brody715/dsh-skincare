# 知识模块写作规范（给写作者）

写 `skill/references/NN-主题.md`。读者是**模型**，不是人——但模型会把你的原文念给用户听，所以每一句都要经得起念出来。

## 1. 唯一可接受的事实来源

所有事实性句子必须有 `[s:<片段>]` 引用。片段的解析方式是「slug 的尾部，必须唯一」，用脚本校验：

```bash
cd /root/dsh-skincare/skill
python3 scripts/lookup.py --topic acne          # 看这个主题有哪些页
python3 scripts/lookup.py --check acne           # 校验一个片段，打印完整 slug + url
python3 scripts/lookup.py --url acne             # 取原文地址（核对细节时去读）
python3 scripts/lookup.py --audit                # 校验 references/ 里所有引用
```

- 写之前**先**用 `--topic` 把可用页面列出来，再从里面挑，不要凭记忆写 slug。
- `[s:x]` 在正文里写作 `[s:xx-yy/zz-page]` 这种尾部形式即可（`--check` 通过就行）。
- 一句结论挂了引用，同一段里后续的展开句不必每句都挂；但**每 3–5 句必须有一处引用**。
- 查不到出处的经验判断，**明确标注**：`（这是我的推断，不是 AAD 原文）`。
- 读原文用 `python3 scripts/lookup.py "<关键词>"` 定位，再 `--url <slug>` 取地址去读；英文原文即可。
  `skill/sources/core/` 是本地自备的原文副本，属第三方内容、**不随包也不入库**；你本地如果有，`--read <slug>` 会直接把正文给你。

**严禁**：编造 slug；把 AAD 原文整段翻译过来当自己的内容（版权）；写出库外来源（Mayo、WebMD、小红书）却不标注。

## 2. 事实与判断必须分开

AAD 说的是事实。你要补的是「普通人怎么执行」。两者格式要能区分：

```markdown
## 洗脸频率
早晚各一次对多数人足够，出汗多的日子可以多一次。[s:skin-care-basics/care/face-washing-101]

> 执行口径（非 AAD 原文）：判断洗得对不对，看洗完 10 分钟不涂东西时紧不紧、是否泛红。
```

`> 执行口径（非 AAD 原文）：` 是固定的标注格式，用于你自己加的判断。

## 3. 不写的三样东西

1. **不写产品名、品牌、价格、链接。** 只写「类别」（氨基酸洁面、广谱防晒、含神经酰胺的保湿霜）。
2. **不写诊断结论。** 不写「你得的是 X」，写「这类表现常见于 X，需要医生确认」。
3. **不写处方与浓度。** 不写「用 0.1% 维 A 酸」，不写「口服异维 A 酸」。

## 4. 结构模板（照这个搭，别自创）

```markdown
# NN 主题名

一句话说清这个模块解决什么问题，以及**什么情况下要转去别的模块**。

## 这一节最该记住的三件事
- （三条，每条 ≤30 字，可直接说给用户听）

## 核心内容
（按小问题分小节，每节 200–400 字。每节结尾给一个「怎么判断」或「怎么执行」的口径。）

## 常见错误（用户最可能正在做的）
- （3–5 条，具体到行为：「用热水洗脸」「防晒只涂早上一次」）

## 什么时候要停下来就医
（指向 `10-何时就医.md` 的具体条款）

## 自测
（3 个场景题 + 答案要点，给讲师角色用）
```

## 5. 篇幅

- 每个模块 **7000–9000 字符**（`wc -m` 口径，含标点与 ASCII 字符）。
- 为什么这么长：0.2.0 起原文副本（`sources/core/`）与中文机翻（`corpus/`）都**不随包发布**，也不进公开仓库。模块必须自己把机制、数值、适用条件、分诊口径讲到能独立回答，不能指望包里有原文可翻。
- 硬上限 9000 字符。超了先删重复解释、删同义复述、合并相邻 bullet，**不要删可执行清单**（数值、步骤、红旗条目）。
- 另一个密度指标：每篇 ≥ 25 个不同 `[s:slug]`。靠拉长句子凑字数不算，能被 `--audit` 追到原文的引用才算。
- 一个模块只讲一个主题。跨主题的内容写成「见 `NN-xxx.md`」，不要复制过来。

## 6. 语言

- 中文短句，结论先行。
- 禁止营销词：「深层清洁」「排毒」「焕新」「屏障修护力」「医用级」「械字号级」——出现时必须是在**拆穿**它。
- 不用「亲」「宝子」「姐妹们」这类口吻。用户是成年人。

## 7. 交付前自检

```bash
cd /root/dsh-skincare/skill
python3 scripts/lookup.py --audit      # 必须 0 problem
wc -m references/NN-*.md               # 每篇 7000–9000 字符
```

再自问三句：
1. 每一段都有出处吗？没有出处的标注了吗？
2. 有没有一句是在给诊断、推产品、报浓度？有就删。
3. 用户读完能**做出一个动作**吗？不能就不是知识模块，是百科。

## 8. 边界（不许越）

- 不做疾病确诊；不做严重程度分级（轻/中/重度由医生定）。
- 不评估用户照片；不做皮肤评分。
- 不做成分打分、成分冲突库、品牌比价。
- 不替医生决定用药、检查、医美项目。
