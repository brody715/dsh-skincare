# A/B 对照：带 Skill vs 普通聊天（v0.1，2026-11-22）

目的：验证 Skill 是否真的比"直接聊天"更可靠。方法、数字、结论都留在这里，方便以后重跑或被人反驳。

## 方法

- 8 个真实用例，覆盖最容易出错的三类：常见误区（b05 化妆后补涂、s05 毛孔能不能缩、a04 爆痘排毒）、鉴别与红旗（a02 红/褐痘印、x01 屏障受损、m01 痣在变化）、边界与做减法（e02 要药、l03 八步流程）。
- 两臂同模型、同题面、同字数要求（250–450 字）：
  - **带 Skill**：先读 `skill/SKILL.md`，按它的按需读取协议、引用格式、输出风格、自检执行。
  - **不带 Skill**：明确禁止读 `/root/dsh-skincare` 下任何文件、禁止调技能、禁止联网，只凭模型自己的知识回答——模拟"普通助手"。
- 机械项用 `eval/ab.py` 算（字数、`[s:...]` 引用数、分诊表达、`cases.jsonl` 里的禁忌词）；答对没答对由人工读全文判。
- 答案原文落在 `/tmp/ab/<id>-with.md`、`<id>-plain.md`，按需复核。

## 人工读出来的差别

**没有想象的大。** 8 个用例里，普通聊天在 s05（毛孔不能真正收缩）、a04（排毒不成立）、x01（先停新产品）、m01（尽快面诊）、e02（拒绝开药）上的结论都对，语气也稳。这一条必须写下来：**基础模型已经把常识讲对了，"更正确"不是这个 Skill 的卖点。**

真正的差别集中在四个地方：

1. **可核验 vs 不可核验。** 带 Skill 每篇 3–8 处 `[s:...]`，可以一路点回 AAD 原文；不带 Skill 0 处，读者只能凭信任。同一句话，前者可被质疑并被查，后者只能信或不信。
2. **细节会漂。** b05 里普通聊天写"全脸大约一元硬币或两指长的量"——一元硬币是保湿的用量口径，防晒是两指长/1 oz；两个标准被并成一句。带 Skill 的版本把两件事分开写，并且给出处。**无来源的模型不是不会错，是错了没人能发现。**
3. **推断和原文分得开。** s05 带 Skill 版有一句漂亮的自律："（这半句是我的推断，不是 AAD 原文）"；b05 带 Skill 版把带妆补涂标成"执行口径，不是 AAD 原文"。普通聊天把同类内容一律当事实陈述——它自己也分不清哪些是 AAD 口径、哪些是流行说法。
4. **做减法。** l03 八步流程，带 Skill 版先点出"八步里六步都在做保湿，而白天最该有的防晒不在里面"，再按保留/停/改/加分类；普通聊天说得也不错（爽肤水与肌底液二选一、乳液与面霜二选一），但没有指出层数结构问题，也没给防晒的用量与补涂标准。

## 结论

- Skill 的收益 = **可核验性 + 口径纪律 + 边界（红旗、拒绝开药、拒绝产品推荐）+ 结构化流程（阶段评估、学习路径、目标打卡）**，不是"知识更多"。
- 所以插件（面板）不该承载知识。它只做一件事：把档案里的今日流程、打卡、学习进度摆在手机上，让人真的执行。这和 `docs/design.md` §11 的划法一致。
- 反过来看风险：如果哪天 Skill 的回答和普通聊天没区别，说明它只剩引用装饰。判断标准是——**把引用全部删掉，答案是否还明显优于普通聊天？** 在 a02（红/褐痘印）、l03（流程结构）、m01（红旗话术）上是的；在 s05、a04 上不是。

## 限制（别把这份结论用过头）

- 只 8 个用例、单模型、单次采样，没有重复跑，方差未知。
- "不带 Skill"臂被禁止读文件，天然拿不到引用；引用数之差不能全算 Skill 的功劳。
- 分诊机械项太松（正则命中即算对），8/8 说明不了红旗能力。要测隐蔽红旗得用 s02（62 岁小腿痒）、x03（新产品红痒）这类，本轮没测。
- 考官是同一个模型，对自家输出有偏好风险；真正的判据是拿去用一周后有没有改变行为（少买、不漏防晒、该就医时去了）。
